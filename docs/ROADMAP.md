# 开发路线

当前状态：仓库初始化。以下里程碑尚未完成；原生 RdpGames 已有能力也需要经过插件集成后的重新验证。

## M1：原生助手接入插件

1. 核对原生源码与依赖的来源、许可证和基线版本，导入必要源码及资产，排除构建输出、日志和私密配置。
2. 保留原生助手现有双端角色及 RDP 通道，新增独立的管理 IPC。
3. 提供自包含 MCP 适配器，支持启动或激活助手、读取状态、停止自己管理的资源。
4. 在宿主提供通用的进程插件打开入口，并同步所需清单及校验规则。

验收：两端安装同一版本插件后，能够从 LingBox 打开助手、选择角色并读取真实状态；停止插件不会关闭 mstsc、游戏或无关助手进程。

## M2：单机游戏模式与恢复

1. 读取 StickyKeys、FilterKeys 等相关系统设置，保存当前用户的原始快照及恢复记录。
2. 只调整必要快捷键标志，不吞掉正常 Shift 输入，不关闭用户已经启用的辅助功能。
3. 协调宿主自身快捷键，展示完整保护、部分保护和需要恢复等实际状态。
4. 实现正常停止、应用退出及下次启动时的恢复处理；恢复失败保留记录和可重试入口。

验收：重复开启和关闭不会覆盖原始快照；正常 Shift 输入保持可用；退出后恢复原值；原先开启的辅助功能保持启用；API 失败不会误报成功。

## M3：双端协同

1. 扩展协议版本和游戏模式能力协商，首版要求两端插件版本一致。
2. 控制端发起启用，被控端明确接受或拒绝，各端只保存和恢复本端设置。
3. 任意一端停止均使旧启用请求失效，处理重复消息、超时、断连与重连。
4. 根据 RDP 前台状态、锁屏和连接状态暂停或恢复保护，保持游戏模式与相对鼠标状态独立。

验收：两端回执及状态一致；切离 RDP、锁屏或断连后恢复实际保护设置；重连不会擅自复用已失效请求；鼠标暂停不会独自关闭仍应生效的键盘保护。

## M4：打包与分发

1. 宿主增加带清单、路径和摘要校验的插件 ZIP 导入。
2. 制作同一份 Windows x64 自包含包，使用约定名称并生成 SHA-256 摘要。
3. 在两台干净 Windows 环境验证首次安装、mstsc 组件注册、升级、卸载及异常恢复。
4. 编写安装教程和已知限制，通过 GitHub Releases 提供已验证的版本。

验收：两端无需额外安装开发 SDK 即可运行；首次组件注册和升级需要重开 mstsc 时有明确提示；卸载只清理本插件拥有的资源。

## 问题处理原则

- 无法配对：先确认已有 mstsc 会话、角色、版本和组件加载状态，不额外开放网络端口。
- 多个 RDP 会话：要求明确选择会话，不猜测目标窗口。
- 组件更新未生效：提示用户自行结束并重开相关 mstsc 连接，不自动中断会话。
- 游戏权限更高：识别权限边界并说明实际限制，不静默提权。
- 系统设置应用失败：尝试回滚，展示失败项；恢复失败继续保留本端恢复记录。
- 异常退出：不承诺任意崩溃后立即恢复，提供断连超时和下次启动恢复，并纳入故障测试。
- 发布包不可下载：检查版本是否正式发布、资产是否齐全及网络连接，不在客户端内置 GitHub 凭据。
